# Deploying Aknologia Usage

This is the free-tier setup we planned: **Neon** (Postgres) + **Render** (one Docker web service that serves the API,
the admin console, and the landing page) + any **SMTP** email provider. Free tiers change; check each provider's
current limits when you sign up.

```
 Developer laptops                         Render web service                    Neon
 ┌──────────────────────┐   HTTPS hourly   ┌──────────────────────────────┐      ┌──────────┐
 │ Aknologia agent      │ ───────────────▶ │ /api/v1/*   API              │ ───▶ │ Postgres │
 │  reads ~/.claude,    │                  │ /app/       admin console    │      └──────────┘
 │  ~/.codex (metadata) │                  │ /           landing page     │ ───▶ SMTP (emails)
 │ Desktop window (UI)  │                  │ /download/  installers       │
 └──────────────────────┘                  └──────────────────────────────┘
```

---

## 1. Create the database on Neon

1. Sign up at **neon.tech** and create a project.
   * **Region:** AWS Asia Pacific (Singapore) is the closest to Chennai.
   * **Postgres version:** 16 or newer.
2. Open **Dashboard → Connection details**.
3. Copy the **connection string**. It looks like:
   `postgresql://neondb_owner:••••@ep-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`
   * Use the **direct** (non-pooled) string; this app opens at most 10 connections. The pooled string also works.
   * Keep `?sslmode=require` at the end.
4. You do **not** need to create tables. The server applies `backend/internal/db/migrations/*.sql` automatically on
   start. To apply them yourself first:

   ```bash
   cd backend
   DATABASE_URL='postgresql://…?sslmode=require' go run ./cmd/server -migrate
   ```

5. Check it worked in Neon's **SQL Editor**:

   ```sql
   SELECT name, applied_at FROM schema_migrations;   -- 001_init.sql, 002_exact_pricing.sql
   SELECT model, input, output, cache_read FROM model_prices ORDER BY model;   -- built-in price list
   ```

Notes: Neon's free compute suspends after a few minutes idle and wakes on the next query (a second or two). The
server retries the first connection for you. Agents sync on the hour, so the database is mostly asleep.

## 2. Set up email (SMTP)

Codes, invitations, removals, and budget alerts are sent by SMTP. Use any provider: Brevo, Resend, Postmark,
Amazon SES, Mailgun, or Gmail with an app password. You need:

| Variable | Example |
|---|---|
| `SMTP_HOST` | `smtp-relay.brevo.com` |
| `SMTP_PORT` | `587` |
| `SMTP_USER` | your SMTP login |
| `SMTP_PASS` | your SMTP key |
| `MAIL_FROM` | `Aknologia <no-reply@yourco.com>` (a sender your provider has verified) |

Without SMTP settings and with `DEV_MODE=true`, emails and codes are printed to the server log instead. That is
fine for a quick trial, but **don't run production in dev mode**: rate limiting is relaxed and codes appear in logs.

## 3. Deploy the server on Render

1. Push this repository to GitHub (or GitLab).
2. In Render: **New → Blueprint**, pick the repository. Render reads `render.yaml` and creates the
   `aknologia-usage` Docker web service. (Or **New → Web Service → Docker** and set the variables by hand.)
3. Fill in the environment variables:

| Variable | Value |
|---|---|
| `DATABASE_URL` | the Neon string from step 1 |
| `APP_SECRET` | generated by Render (any long random string) |
| `PUBLIC_URL` | your service URL, e.g. `https://aknologia-usage.onrender.com` (no trailing slash) |
| `SMTP_*`, `MAIL_FROM` | from step 2 |
| `SYNC_MINUTE` | `0` (agents sync at minute 0 plus up to 2 minutes of jitter) |
| `TRUSTED_PROXY_HOPS` | `1` on Render (set by `render.yaml`): its proxy adds the client address to `X-Forwarded-For`, which the login rate limit uses. `0` (default) when nothing sits in front of the server. |
| `DOWNLOAD_URL` | optional; defaults to `$PUBLIC_URL/download/` |

4. Deploy. When the build finishes, check:
   * `https://<your-service>/api/v1/health` → `{"ok":true,…}`
   * `https://<your-service>/` → landing page
   * `https://<your-service>/app/` → admin sign-in

Free Render services sleep after about 15 minutes without traffic; the first request then takes up to a minute.
Agents simply retry at the next window, and nothing is lost: events wait on each laptop until they're accepted.

**Custom domain (optional):** Render → your service → Settings → Custom Domains, then update `PUBLIC_URL`.

## 4. Create your workspace

1. Open `https://<your-service>/app/#/signup` → **Create workspace**.
2. Enter the 6-digit code from your email. You're now the first admin.
3. **Settings and billing → Plan and billing → Change plan or seats** to set seats (Starter allows 3).
4. **Budgets and alerts:** set the team default budget and the alert inboxes.

## 5. Build and publish the desktop app

Build on each operating system you support (Wails builds natively; it doesn't cross-compile macOS or Windows apps).

**One-time setup on the build machine**

* Go 1.22+ and Node 20+
* Wails CLI: `go install github.com/wailsapp/wails/v2/cmd/wails@v2.9.2`, then run `wails doctor`
* macOS: Xcode command line tools (`xcode-select --install`)
* Windows: the WebView2 runtime (preinstalled on Windows 11)
* Linux: `sudo apt install libgtk-3-dev libwebkit2gtk-4.0-dev`

**Build**

```bash
SERVER_URL=https://<your-service> VERSION=1.0.0 ./scripts/build-desktop.sh
```

This builds the window and the agent with your server address built in, and writes
`landing/download/aknologia-usage-{macos.zip,windows.zip,linux.tar.gz}`. Those files are git-ignored (so build output
isn't committed by accident), so a deploy from git won't include them. Publish them one of two ways:

* **Recommended:** upload them to a release page (for example GitHub Releases) and set `DOWNLOAD_URL` to that page;
  invitation emails link there.
* Or serve them from this server: remove the two `landing/download/*` lines from `.gitignore`, commit the files, and
  redeploy. The `/download/` page links to them.

Until they're published, the `/download/` page says "Not published yet" instead of showing broken links.

The builds are unsigned, so macOS Gatekeeper and Windows SmartScreen will warn on first open (right-click → Open on
macOS; "More info → Run anyway" on Windows). For an org-wide rollout, sign with an Apple Developer ID and a Windows
code-signing certificate.

**What the desktop app does on first run**

1. The window starts the bundled `aknologia-agent` (it then starts itself at every login).
2. The member chooses **I have an invite**, enters their email and invite code, and sets a password.
3. The agent scans `~/.claude/projects` and `~/.codex/sessions` (or `$CLAUDE_CONFIG_DIR` / `$CODEX_HOME`) and
   syncs at the next hourly window. **Force sync** sends immediately.

Agent data lives in `~/Library/Application Support/Aknologia` (macOS), `%AppData%\Aknologia` (Windows), or
`~/.config/Aknologia` (Linux): `events.jsonl`, `state.json`, `cursors.json`, `agent.log`, `agent.token`.

## 6. Invite the team

**Members → Invite members**, paste emails, choose role and budget. Each person receives an invite code (valid 14
days) and the download link. Removing a member revokes their sessions; their agent stops tracking at the next sync
and they get an email.

## 7. Check prices

Spend is the API-equivalent cost of every request at the vendors' list prices, priced one request at a time the way
the API bills it: 5-minute and 1-hour cache writes, cache reads, long-context tiers (Claude Haiku 5.5 over 100K
prompt tokens, GPT-5.5 over 272K), fast mode, US-only inference (x1.1) and web searches ($10 per 1,000).

* The price list ships with the server in `backend/internal/pricing/catalog.json` (sources and check date inside) and
  is copied into the `model_prices` table on every start. A new release with updated prices updates it.
* Models are matched by exact ID after removing date suffixes, `[1m]`, and Bedrock/Vertex prefixes. A model with no
  price is **never guessed**: its requests are left out of spend and listed under *Data health → unpriced models*.
* To add or override a price without a release, insert a `custom` row (it wins over the built-in row with the same
  date), then press **Refresh data**, which re-prices every stored request:

```sql
-- USD per million tokens. effective_from: first day this price applies (earlier requests keep earlier prices).
INSERT INTO model_prices (provider, model, effective_from, source, input, cache_write_5m, cache_write_1h, cache_read, output)
VALUES ('openai', 'gpt-5-codex', '2000-01-01', 'custom', 1.25, 0, 0, 0.125, 10);
```

Negotiated discounts aren't modelled: spend is what the same requests would cost at list price.
To check the numbers against your own session files, see `tests/api/verify-pricing.mjs`.

## 8. Check that data is flowing

* Admin console → **Team overview → Data health**: devices synced in the last 2 hours, outdated app versions,
  unread lines.
* Neon SQL Editor:

  ```sql
  SELECT u.email, count(*) AS events, max(e.ts) AS latest
  FROM usage_events e JOIN users u ON u.id = e.user_id GROUP BY 1 ORDER BY 3 DESC;
  SELECT name, kind, last_sync, app_version, unread_lines FROM devices ORDER BY last_sync DESC NULLS LAST;
  ```

* On a laptop: `aknologia-agent -scan-once` prints how many files and events it found.

## Rolling back

* **Server:** Render → your service → Events → pick the previous deploy → **Rollback**. The schema is additive, so
  older builds keep working.
* **Database:** Neon → Branches → restore to a point in time (within your plan's history window).
* **Desktop:** publish the previous zip on `/download/`. Agents keep their local `events.jsonl`, so if the server
  ever loses data, set `"synced": 0` in an agent's `state.json` and it resends everything (duplicates are ignored).
